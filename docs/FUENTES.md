# Fuentes y herramientas utilizadas
 
| Fuente / herramienta | Finalidad | Cómo se verificó su aporte |
|----------------------|-----------|----------------------------|
| Documentación de Django — docs.djangoproject.com | Vistas, formularios (`Form` y `ModelForm`), `ImageField` y `request.FILES`, `ClearableFileInput`, autenticación, sesiones, `SlugField` y `slugify`, `on_delete=PROTECT` y `ProtectedError`, `PermissionDenied`, `require_POST`, y `dumpdata` / `loaddata` | Se probó cada ruta y cada formulario en el navegador (ver `COMPROBACIONES.md`, secciones A a L) |
| Documentación de Django sobre bases de datos y PostgreSQL — docs.djangoproject.com y psycopg.org | Configurar `DATABASES` con PostgreSQL, el driver `psycopg` y el reinicio de secuencias tras `loaddata` | Se aplicaron las migraciones sobre una base vacía y se comparó la cantidad de registros antes y después del traslado (ver `COMPROBACIONES.md`, sección G) |
| Documentación de PostgreSQL — postgresql.org | Crear la base `wuwa_tracker_DB` y el usuario de conexión | Se creó la base desde cero siguiendo el README y se comprobó con `connection.vendor` (ver comprobación 37) |
| Documentación de Pillow — pillow.readthedocs.io | Leer el ancho y alto de la portada del banner para validar su resolución y proporción | Se subieron imágenes válidas, pequeñas y con proporción fuera de rango (ver comprobaciones 84 a 87) |
| Proyecto de ejemplo del docente (`anuncios`, app `diariomural`) | Guía de la lógica: subir imágenes con `ImageField` + `enctype="multipart/form-data"` + `request.FILES`, plantilla "maestra" con includes, y slugs en las rutas de detalle | Se comparó el flujo con el de este proyecto y se comprobó creando un item con imagen desde el formulario (ver comprobaciones 22 y 32) |
| django-crispy-forms + crispy-bootstrap5 | Mostrar formularios (login, simulación, items y banners) con estilos y errores por campo | Se enviaron los formularios con datos inválidos y se vio el mensaje de cada campo |
| Bootstrap 5 y fuentes locales | Estilos base de la interfaz | Revisión visual en el navegador |
| Prydwen — prydwen.gg/wuthering-waves (páginas de stats y de armas) | Ataque base a nivel 90 de los 16 personajes y 10 armas, y estadística secundaria de las armas | Se comprobó que los nombres coincidieran con los 26 items de la base. Comparamos con otras páginas o wikis para tener los datos reales y ver que concordaran. |
| Sportskeeda y PCGamesN (guías de armas de *Wuthering Waves*) | Efectos de algunas armas (regeneración de energía y bonos de ataque) usados en las descripciones | Las descripciones se redactaron con palabras propias, no se copió el texto del juego. Se hizo según lo que sabíamos |
| wuthering.gg/es | Nombres de personajes y armas del fixture `datos_iniciales.json` e imágenes | Nombre para todos los personajes y armas que se ven en la página |
| Imágenes oficiales del juego (banners de arma y de personaje) | Portadas de los banners de prueba | Se subieron desde el formulario y se comprobó su validación y su visualización (ver comprobaciones 84 y 88) |
| Git y GitHub | Control de versiones del proyecto, con commits separados por cambio | Historial de commits del repositorio |
| Claude (Anthropic), asistente de IA | Revisión del proyecto contra la pauta; apoyo para la migración a PostgreSQL, el CRUD de banners e items con sus permisos y restricciones, la portada opcional del banner (campo, validación y vista), los campos `descripcion` y `ataque_base`, las validaciones de `ItemForm`, scripts de carga de datos de un solo uso, y la redacción del README y de las comprobaciones; búsqueda de los datos del juego | Cada cambio se ejecutó y probó localmente antes de incorporarlo (ver `COMPROBACIONES.md`), y los scripts de un solo uso se retiraron después de ejecutarse |
